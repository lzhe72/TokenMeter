## 构建、迁移与顺序

1. 锁定 TM-001→TM-004 已实际验收的源码、测试绑定和上一**真正稳定**本地 DMG。SOP-007 对 0.2.0 起的版本要求从上一实际稳定包自动更新到最终候选；若到本版仍无稳定前版，则本版升级门禁 BLOCKED，不能用 0.1.0 首版的候选→受控高版特例代替，也不能把未发布的 0.4 草案包冒充稳定版。
2. 锁定候选提交、Electron/npm lock、原生双来源版本、客户端 schema 与价格无关的用量迁移方案。打包前核对本机签名/安装条件、所有测试 Keychain item 的隔离归属、动态端口、合成服务/SQLite 和受控源目录；缺一项仅阻断依赖场景，最终完整门禁仍不放行。
3. 若认证服务需要兼容改动，先在隔离服务/库升级并核对 `/v1/me`、账号和会话，后安装客户端。TM-005 不新增服务端用量 API，不迁移用户生产服务库。客户端 schema 变更先按 SOP-016 备份拥有的旧 profile 副本、验证可恢复，执行迁移并核对每主体/来源唯一调用数、token、未知值与覆盖状态；失败停止应用写入。
4. 从 `dmg/<release_id>/` 的未发布候选入口回指原包，安装同一最终 DMG；执行全部 TM-005 细 TC、两个 E2E 场景组及此前已交付功能完整回归。机器门禁核对精确 TC 集合、双来源原生输入、原始逐步结果、清理、候选 SHA/tree、包/数据/程序摘要及独立结果 Excel；零例、跳过、失败、阻断、重试取绿或摘要不符均不得签通行证。

## 故障停止与恢复

任何源授权/Keychain 身份不明、客户端迁移失败、扫描覆盖不可证、认证服务健康检查失败、自动更新未实际替换、包签名/摘要不符时停止发布并保留原始失败。只在隔离副本验证过恢复后，使用本轮已拥有的迁移前客户端库备份和上一真正稳定签名包恢复；核对旧账号、已采集调用数、来源身份和可读状态，不把源文件重扫造成的重复当恢复。未验证恢复方案时状态为 BLOCKED，不能先分发再补证据。故障处理按 SOP-015/021，修复后新候选完整回归。
