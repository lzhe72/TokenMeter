# TM-005 技术设计与开发计划草案

**release_id：** `v0.5.0-20261001T034729Z`

来源无关的字段、状态、日期与 IPC 约束详见[03a 统计读取合同](03a-statistics-contract.md)；以下保持实施顺序和需要上游核实的边界。

## 技术设计（SOP-004）

目标数据流：已授权的 Codex 和 Claude Code 原生日志 → 对应已验证版本适配器 → 可信事件/诊断及覆盖证明 → 客户端隔离 SQLite → 主进程的限定统计查询 → preload 明确业务方法 → React 界面。两来源均为本版验收输入。TM-007 前不依赖团队服务的用量同步，登录仍走真实 FastAPI/隔离服务库；统计只显示当前登录身份在本机授权来源中的用量。

事件合同须包含稳定来源事件身份、来源类型/模型、UTC 时间、当前身份归属、input/output、缓存/推理子项、各字段的 known/unknown 状态及可追溯诊断码；原始路径只在本机采集边界使用，持久记录不得包含完整路径或正文。覆盖需独立存储已扫描且可信的时间区间及不确定区间，空事件集合本身不能证明“零调用”。来源解析与去重属于 TM-003/004，本版只查询其持久化结果，不以 UI 层去重掩盖采集失败。

查询用团队时区将当地日界转换为 UTC 半开区间，同一窗口内汇总/趋势/明细/模型分组使用同一事件集合和同一可信度规则。`null`/未知字段不得参与数值加法后被当作完整合计；可展示已知部分并标注不完整。刷新和重启从本地事务化记录重查。自定义日期的错误范围必须明确拒绝，不查询或写入源数据。时区变化仅改变分桶，不改事件 UTC 时间。

schema 与迁移版本、覆盖证明如何由 TM-003/004 提供、不同登录身份在同一设备上的隔离边界、无历史稳定包时的升级基线，均需在依赖工程可用时核对。涉及客户端 schema 时执行 SOP-016 的备份、迁移、核对与恢复设计。

只读核对 TM-001 干净候选 `3467dc143b2e2fc71f51515f483f0ecff8637947`：Electron 框架已有 `apps/desktop/src/shared/types.ts` 的固定 `Bridge`/`Snapshot`、preload 的 `tokenmeter:invoke` 与主进程逐方法分发；这些接口目前仅覆盖账号、配置和更新。TM-005 将在采集 schema 基线后扩展明确的统计业务方法、同窗只读快照与 React 视图，并保持现有主窗口/主 frame 校验和 renderer 不直连库的边界。该候选没有用量 SQLite 或统计 IPC，且尚无最终 DMG 产品门禁，故这里只记录可供后续对齐的接口事实。

## 开发顺序（SOP-005）

1. `TASK-TM005-EVENT-CONTRACT`：与两项采集 schema 对齐，明确未知/覆盖和身份隔离。验收见 `TC-TM005-CONTRACT-01` 至 `10` 及两个冲突变体；当前缺真实采集实现。
2. `TASK-TM005-DATA`：固化原生日志映射、独立 oracle、日期/时区/缺失数据及所有权清理。验收见 `TC-TM005-DATA-01/02` 草案。
3. `TASK-TM005-RANGE-QUERY` 与 `TASK-TM005-COVERAGE`：实现限定查询及覆盖/未知分类，先建立固定失败基线。验收见 `TC-TM005-RANGE-01` 至 `11`（含空日期与 DST 变体）、`TC-TM005-STATE-01` 至 `06` 草案。
4. `TASK-TM005-UI`：限定 IPC/React 视图及重启恢复。验收见 `TC-TM005-MODEL-01/02`、上述范围/状态 TC。
5. `TASK-TM005-E2E`：在 TM-003/004 固定用例和数据稳定后扩展当前仅接受 `TC-TM001-*` 的固定执行器与精确集合门禁，把每个 TM-005 父 TC/变体绑定到仓库固定 Playwright Electron 程序，使用安装后的 App、真实服务与隔离库；固定治理负测至少拒绝缺例、错来源、跳过、重试取绿和摘要不符。执行 TM-005 全部 TC 和此前已交付功能全部 E2E；发布前另经 SOP-017/018。不能只修改 TM-001 gate fixture 数量来声称本版已覆盖。

当前工作树已有根机器用例目录及项目总表，但仍缺 Electron 产品源码、TM-003/004 采集及客户端用量库，无法完成业务红测或实现。`python3 scripts/check_tm005_bindings.py` 只校验 32 条父 TC、6 个变体的目录关系，并报告 38 个缺失的产品绑定；其 BLOCKED 输出不能当作产品测试。待采集合同稳定后补齐逐 TC 的实际原生日志输入、每步断言、SQL/清理与程序入口，再运行 SOP-008 基线检查。
