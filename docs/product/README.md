# 产品约定

状态：已确认的首版范围，功能尚未实现。实现与测试状态以 [功能矩阵](../../tests/feature_matrix.json) 和执行证据为准。

## 用户与采集范围

- 一个部署服务一个团队。管理员预置账号，无开放注册；成员只能查看自己的数据，管理员可查看团队。
- 首版只读本机 Codex、Claude Code 已有日志，含可核实的子代理用量。用户授权目录后导入并增量读取，不修改工具配置、不代理请求。
- 统计日志中可识别的模型，如 GPT、Sonnet、Opus、Qwen、GLM；未知模型保留原始标识。支持模型不能等同于支持所有调用该模型的应用。
- 不采集对话或代码正文。界面显示已发现时间范围、缺失字段、未知格式、最后采集/同步时间。

## 固定口径与默认值

- 存储时间 UTC；团队默认 Asia/Shanghai。近 N 天包含今天，按自然日分组。
- 首次导入默认最近 30 天，可调整；不存在的历史不能补零。
- 输入/输出、缓存读取/写入、推理 Token 按来源语义标准化，子项不能重复加入总数。
- 日志包含请求标识时才统计请求数；日志行数不是请求数。
- 估算费用保留价格版本，不把订阅折算值称为实际账单；首版不自动换汇。
- 文件变更触发读取，每 30 秒补扫；每 60 秒同步，支持手动刷新。App 退出后停止采集，下次补扫。
- 本地用量默认保留 90 天，服务器 365 天，可配置；按团队时区的自然日计算并包含今天，仅清理早于保留首日 00:00 的事件。客户端未确认上传的数据不受常规过期清理影响。
- 未分配项目归入“未归属”；项目映射由用户明确设置。
- 初始平台 macOS 14+，Apple Silicon 和 Intel；发布支持矩阵必须用真实 runner 证据证明。

## 成功标准

同一组确定性数据重复扫描、重启、断网补传后，个人与团队结果仍与独立预期一致；成员不能查看他人数据；每项已交付功能的自动 E2E 在同一候选提交上通过。缺少任何证据时不能发布。

## 分阶段交付边界

- 0.1.0 验收真实 App→认证接口→账号数据库→界面的登录与账号管理链路，成员本人身份与管理员操作权限必须由服务端校验。统计越权和停用账号上传在 0.7.0 的同步/统计链路中验收。
- 0.2.0 验收目录选择、候选文件预览、授权保存与恢复，记录采集/同步意愿；按日志内容识别时间/用量以及重新授权后的去重在 0.3/0.4.0 验收。0.3/0.4.0 同时提供必要的采集状态及用量核对界面；0.5.0 再交付完整日期筛选、趋势和明细。
- 0.1.0 包含最小签名更新器作为持续交付基础：HTTPS 版本发现、点击升级、签名校验、失败保持原版。首次无历史稳定版时，验证候选干净安装，再由该候选升级至受控高版本签名测试包；测试包仅用于隔离验证，不作为公开发布。自 0.2.0 起，每次发布均从上一公开稳定版验证自动更新。0.10.0 完善更新设置、版本说明与异常体验，不能把早期版本交付为没有更新器的安装包。
- 数据库初始化与随版本 schema 变化所需的兼容/恢复检查从首项功能开始；0.11.0 交付面向用户的完整备份、恢复与数据库迁移能力。版本依赖详见[路线图](../roadmap.md)。
