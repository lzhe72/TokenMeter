# 已确认的输入与最高约束

来源：本项目用户在设计讨论中明确提出和选择的要求。本记录是文档体系的输入，不代表产品已经实现。

## 最高约束

1. 规范驱动文档，文档驱动设计、开发、测试、发布和产品迭代。
2. 每一步必须有 SOP；根 sop/README.md 为总索引，每项工作一份独立文件，按步骤拆分。AGENTS.md 强制第一步查索引，再完整读对应 SOP、验证输入输出并保存证据；缺失或冲突先按 SOP-000 修订。
3. 先建立需求→功能拆解→开发计划→测试计划→发布预案的框架和文档，再按文档开发、验证、发布，之后进行下一轮迭代。
4. 项目由大模型开发，需要 AGENTS.md、docs、状态和交接记录，便于 Codex 理解、修复和继续迭代。
5. 每项功能都有测试用例及测试数据；所有测试账号和数据同时具备程序与 SOP。Codex 自动编写、执行、判断门禁；每次迭代和发布均须 E2E 通过才可上线。
6. Changelog 标题为版本；Git 发布编号包含版本号和时间。一个编号可查询需求、功能拆解、开发/测试计划、用例、发布文档、通行证及 Git 发布。

## 产品范围决定

- macOS 桌面 App TokenMeter；首版只读 Codex 和 Claude Code 已有本地日志，记录日志中可识别的 GPT、Sonnet、Opus、Qwen、GLM 等模型。
- 首次启动引导权限授权；不改用户 API 地址、不引入代理。其他 App/独立 API 来源后续适配。
- 团队集中管理，一套服务一个团队；预置账号，无开放注册。
- 今天、昨天、近 7/15/30 天可配置；Token 与费用估算。
- 本地数据库文件，生产服务端采用 MySQL；自动发现版本，用户点击更新。
- 一项功能一个版本，小功能升次版本，重大功能升主版本；每版有 Changelog 并提交 Git。

## 设计采用的默认值

SwiftUI 客户端、FastAPI 服务端；UTC 存储、Asia/Shanghai 团队默认时区；近 N 天含今天；macOS 14+ 通用安装包。具体数据保留、同步、价格、功能拆解及测试矩阵见产品和架构文档，后续变更遵循 SOP-000/024 并更新版本档案。
