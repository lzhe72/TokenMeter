# 版本路线图

## 从第一项功能开始执行门禁

测试基础设施是 0.1.0 的前置条件。每个版本同步交付用例、造数/重置程序、SOP、自动 E2E 和结果；不能等到 1.0 才补 E2E。

| 版本 | 功能 | 测试要求 |
| --- | --- | --- |
| 基础规范，未发布 | AGENTS/docs、可复现数据工具、门禁入口 | 工具自测通过；产品 E2E 明确 BLOCKED |
| 0.1.0 | TM-001 预置账号与登录；本机服务默认值与可配置地址；最小签名更新器交付基础 | 接通真实 App/服务端/数据库 E2E，验证本人身份、账号管理权限、隔离服务切换；干净安装及受控签名更新演练 |
| 0.2.0 | TM-002 授权引导 | 自动验证目录选择、候选文件预览、真实授权及拒绝/恢复，不依赖用量解析 |
| 0.3.0 | TM-003 Codex 采集 | 版本化原生日志、累计去重、重新授权恢复及最小采集核对界面 |
| 0.4.0 | TM-004 Claude Code 采集 | 子代理、分支历史、重复写入与重新授权后的去重 |
| 0.5.0 | TM-005 用量统计 | 固定时钟、日期边界、可信预期 |
| 0.6.0 | TM-006 费用估算 | 价格快照、缓存、未知价格、价格历史、多币种及订阅估算；扩展数据尚待实现 |
| 0.7.0 | TM-007 团队同步 | 断网、重启、幂等、统计权限隔离及停用账号上传拒绝 |
| 0.8.0 | TM-008 CSV 导出 | UI 筛选至导出内容闭环 |
| 0.9.0 | TM-009 预算提醒 | 阈值、周期、幂等及通知权限 |
| 0.10.0 | TM-010 完整更新体验 | 在最小更新器上完善设置、版本说明、异常恢复；生产服务器确定后验证新 HTTPS 默认地址只迁移未手动配置用户；继续从上一稳定版自动安装/迁移/重启 |
| 0.11.0 | TM-011 数据迁移与恢复 | SQLite/MySQL 一致性及恢复演练 |
| 0.12.0 | TM-012 菜单栏与诊断 | 状态、暂停恢复、开机启动 |
| 1.0.0 | 首版生产验收 | 全功能、全支持矩阵、签名发布物与升级验证 |

最小更新器在 0.1.0 随工程基础交付，含 HTTPS 更新发现、点击升级、签名校验与失败保持原版；首次通过候选干净安装和候选→受控高版本签名测试包演练验证，自 0.2.0 起每版验证上一公开稳定版→候选的实际自动升级。受控测试包只进入隔离更新源，不创建公开产品版本；手动覆盖安装不能替代此自动更新证据。TM-010 验收完整体验，不是第一次加入更新器。

本机 `127.0.0.1:49176` 是 0.1.0 的首次默认地址，不代表远程 Mac 可访问本机服务器。生产服务器的 HTTPS 地址目前未确定；若它在 0.10.0 以前就绪，应在对应版本立项时前移 TM-010-003 的默认地址迁移验收及真实升级数据。

TM-011 的数据库基础、schema 兼容及必要恢复在相关功能中建设，0.11.0 验收完整迁移/恢复能力。跨功能测试在依赖已交付后加入：账号权限在 0.1.0 验证本人身份/管理员操作；他人统计和停用账号上传在 0.7.0 验证；授权恢复后的用量去重在 0.3/0.4.0 验证。任何已交付场景随后均加入持续回归。

功能前序在[功能矩阵](../tests/feature_matrix.json)的 `depends_on` 中登记。检查程序拒绝引用后续版本或形成依赖循环；进入实现阶段还要求前序功能已实现。所需数据范围由[验收清单](../tests/acceptance.json)的 `data_requirements` 定义，不能用只有部分基础样例的数据集替代。

版本采用 `MAJOR.MINOR.PATCH`：功能升 MINOR，修复升 PATCH，重大升级升 MAJOR。一个功能版本可以包含多个开发提交；Git tag 仅标记通过发布门禁的候选，不为当前规范基础创建产品版本。
