## E2E-TM002-001 · 首次授权、预览与确认

**验收：** `AC-TM002-001`，真实系统授权完成，只读取选定目录；确认前不开始持续扫描；选择和同意状态可在重启后恢复。

**前置/数据：** 数据集 `system_permissions`；全新测试账号登录；专用临时根有待授权目录A与未授权目录B，分别含可识别的合成日志与唯一哨兵文件；不得使用真实 ~/.codex 或 ~/.claude。system_permissions 尚缺目录/授权状态生成及清理程序；相关原始日志须待TM-003/004确认版本后生成。

**步骤：**

1. 从首次启动引导打开系统目录选择器，只选择A；先不确认持续采集。
2. 查看预览，逐项核对显示的候选文件只来自A；在A和B各追加一个不同哨兵事件，观察确认前读取记录。
3. 从引导明确确认采集和同步意愿；核对系统授权完成、保存目录与意愿状态。
4. 退出进程并启动，检查已确认目录与意愿恢复；拒绝选择B时，确认其未进入已授权列表。

**独立预期：** 未确认前不得开始持续扫描；预览和后续读取范围均不包含B。重启保留A与真实同意状态。是否产生用量在采集版本另验，不能要求授权版本依赖尚未实现的解析器。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺可重置的系统授权fixture、原生目录选择与引导UI绑定、访问范围观测方式；暂无造数SQL，权限状态须由系统授权程序创建，不以直接写数据库替代授权。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。

## E2E-TM002-002 · 拒绝、失效与重新授权

**验收：** `AC-TM002-002`，App 不崩溃、不继续读取失效目录；重新授权后可读取目录并恢复授权状态。

**前置/数据：** 数据集 `system_permissions`；账号已登录；专用目录A。分别准备“从未授权”和“曾授权后权限失效”两个隔离状态，权限变更只作用于测试目录/测试域。system_permissions 生成/重置程序未实现。

**步骤：**

1. 干净状态打开系统选择器并取消或拒绝；返回App，检查错误/待授权状态。
2. 重新选择A并确认，再由fixture撤销测试目录访问或使保存授权失效；触发读取并重启App。
3. 检查App保持响应，显示目录需要重新授权；向失效目录追加哨兵，核对没有继续读取。
4. 通过真实选择器重新授权A，确认状态恢复；再次重启并验证可读取该目录的测试文件。

**独立预期：** 拒绝不会崩溃或隐式授权；失效后停止读取，重新授权后恢复访问和持久授权。此例不证明已解析事件去重，恢复去重分别由TM-003-004/TM-004-004验证。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺拒绝/撤销的系统级fixture、权限观测与原生绑定；无业务SQL可替代该系统过程。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。
