# 07 · TM-007 团队同步：详细测试用例

需求：`REQ-TM007`。规划版本：`0.7.0`。功能与全部用例为 **planned**，未执行产品 E2E，无 PASS 证据和发布资格。以下是待实现用例规格；步骤具体描述目标行为，缺少的程序和环境逐项列明。不能把文档完整误报为用例可执行。

## 共用前置与执行规则

依赖功能：`TM-001`、`TM-003`、`TM-004`、`TM-005`。进入实现前按 [SOP-006](../../../sop/SOP-006-test-plan.md) 确定当轮版本/平台矩阵，按 [SOP-010](../../../sop/SOP-010-test-data.md) 建立数据、SQL、独立 expected 及重置程序，再按 [SOP-011](../../../sop/SOP-011-test-implementation.md) 绑定真实测试；执行遵循 [SOP-014](../../../sop/SOP-014-e2e.md)。账号只用合成测试用户，所有数据库、日志、授权和设置均隔离；不得用用户生产库造数。

下面给出的规划数字用于约束独立预期，并不声称已经生成对应厂商日志。原始格式、UI标识、测试函数和SQL尚未确定的部分，必须在该功能开发前补齐；不得发明当前不存在的执行命令。未来版本的测试平台以当轮设计为准，当前v0.1.0只声明macOS15 arm64/Intel。

## E2E-TM007-001 · 离线、重启和补传幂等

**验收：** `AC-TM007-001`，队列持久化，最终个人/团队总量一致且无重复。

**前置/数据：** 数据集 `sync_faults`；sync_faults planned；alice两个隔离设备A/B，设备A调用100/10、B调用200/20；真实FastAPI/SQLite服务，可由外部fixture断网/恢复。账号继续用隔离测试fixture。

**步骤：**

1. 服务可达时登录两设备并建立真实认证，随后由fixture阻断网络。
2. 分别追加调用并等待App采集，检查各自上传队列未确认状态；退出并重启App。
3. 恢复网络，观察持久队列补传及服务端确认。
4. 重放相同上传批次并再次刷新，分别查看alice个人和管理员团队统计。

**独立预期：** 离线重启不丢队列；恢复后2唯一调用、input300/output30/total330；重复批次不再加量。客户端只在真实确认后标已同步，个人合计与对应团队子集一致。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺网络故障注入/恢复程序、设备/raw/队列fixture与SQL、幂等接口/统计UI原生绑定。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。

## E2E-TM007-002 · 部分确认、中断和账号切换

**验收：** `AC-TM007-002`，已确认数据不丢失、不重复；数据归属不能由客户端越权改变。

**前置/数据：** 数据集 `sync_faults`；准备alice的三条唯一事件A/B/C，总量各110/220/330；控制服务仅确认A后断开，B可能已提交但响应丢失，C未提交。另有bob账号。故障注入必须在真实服务外部或明确测试环境中完成，不能绕过认证。

**步骤：**

1. 以alice采集三事件并发送，触发部分确认及连接中断，记录客户端队列和服务端落库身份。
2. 重启App再恢复服务，允许重发未确认B/C，检查A不丢失且B不重计。
3. 从App退出/解绑alice，切换bob，在仍有alice来源记录的环境触发同步。
4. 管理员查询两成员与项目归属，核对已确认事件及队列标记。

**独立预期：** 最终alice的A/B/C各一次、total660；响应丢失不造成B重复；bob不能承接或篡改alice既有事件归属。切换时旧队列按已批准归属策略隔离，不能默认为新登录账号。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺部分确认/事务中断可重现程序、账号解绑及队列归属策略细则、数据SQL与原生绑定，策略需在对应技术设计定稿。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。

## E2E-TM007-003 · 上传白名单与项目映射

**验收：** `AC-TM007-003`，仅允许用量白名单字段；无正文/密钥/完整路径；未归属项目可明确分配。

**前置/数据：** 数据集 `sync_faults`；合成日志包含唯一正文/代码/API-key/完整路径哨兵，以及合法用量/必要去重元数据；只用假值。准备已归属项目A和未归属事件B，待sync_faults生成。

**步骤：**

1. 通过App采集两类事件并向真实测试服务同步，fixture在服务边界记录脱敏请求字段名及哨兵是否出现。
2. 核对每层JSON只含设计批准的字段白名单，搜索所有四类假敏感哨兵。
3. 从App将未归属事件分配到授权项目，提交并刷新。
4. 重启再同步，核对项目状态、原事件身份及统计未重复。

**独立预期：** 网络载荷/持久服务数据均不得含正文、代码、key或完整本机路径；只有批准用量/去重字段。B可明确分配，分配不增加事件量、也不跨团队归属。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺版本化上传白名单、哨兵原始日志生成器、请求检查器、项目管理UI与SQL；日志证据应只报告哨兵命中布尔值/字段，不能上传真实秘密。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。

## E2E-TM007-004 · 统计越权与停用后上传

**验收：** `AC-TM007-004`，服务端拒绝越权统计与停用账号上传；UI 显示错误，他人数据不泄露，队列不误标为已确认。

**前置/数据：** 数据集 `sync_faults`；alice项目A调用100/10，bob项目B调用200/20；成员alice与管理员独立会话；alice另有一条未确认调用C=50/5。sync_faults与可重建统计SQL尚未实现。

**步骤：**

1. alice从UI查询本人及授权范围；通过UI入口和直接API参数分别尝试bob个人、项目B和团队汇总。
2. 管理员从真实App停用alice，保留其已登录App和未同步C。
3. 触发alice刷新统计/上传，检查UI错误和服务端响应。
4. 管理员核对服务端事件、alice本地队列及审计，确认未授权结果没有返回或缓存泄漏。

**独立预期：** 成员无权请求被服务端拒绝，UI不显示bob的220；停用后旧会话及上传拒绝，C不能标为已确认；合法历史不能被失败上传删除。此处补足TM-001仅身份/管理接口权限的范围。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺统计授权API/原生页面、停用上传故障fixture、队列核对与SQL；不能以账号测试002通过代替。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。
