# 03 · TM-003 Codex 采集：详细测试用例

需求：`REQ-TM003`。规划版本：`0.3.0`。功能与全部用例为 **planned**，未执行产品 E2E，无 PASS 证据和发布资格。以下是待实现用例规格；步骤具体描述目标行为，缺少的程序和环境逐项列明。不能把文档完整误报为用例可执行。

## 共用前置与执行规则

依赖功能：`TM-001`、`TM-002`。进入实现前按 [SOP-006](../../../sop/SOP-006-test-plan.md) 确定当轮版本/平台矩阵，按 [SOP-010](../../../sop/SOP-010-test-data.md) 建立数据、SQL、独立 expected 及重置程序，再按 [SOP-011](../../../sop/SOP-011-test-implementation.md) 绑定真实测试；执行遵循 [SOP-014](../../../sop/SOP-014-e2e.md)。账号只用合成测试用户，所有数据库、日志、授权和设置均隔离；不得用用户生产库造数。

下面给出的规划数字用于约束独立预期，并不声称已经生成对应厂商日志。原始格式、UI标识、测试函数和SQL尚未确定的部分，必须在该功能开发前补齐；不得发明当前不存在的执行命令。未来版本的测试平台以当轮设计为准，当前v0.1.0只声明macOS15 arm64/Intel。

## E2E-TM003-001 · 增量采集、重扫、重启和移动

**验收：** `AC-TM003-001`，用量与独立预期一致，同一源事件只计一次。

**前置/数据：** 数据集 `codex_raw`；依赖TM-001/002；已授权隔离Codex目录。codex_raw 须声明真实支持的工具版本、字段语义和来源。规划三次调用A/B/C的独立增量分别为 input/output 100/10、200/20、300/30，缓存20/40/60为input子项；原始格式尚未绑定。

**步骤：**

1. 从空客户端库启动App，在授权目录追加仅含A的该版本原生JSONL；等待文件变化/补扫完成。
2. 继续追加B、C，核对解析事件与读取游标；由产品诊断/后续统计接口观察持久记录。
3. 重复手动刷新和补扫同一文件，退出进程再启动；比较前后持久记录。
4. 在同一授权根移动日志文件后再次扫描；核对源事件身份与计数。

**独立预期：** 唯一事件=3，input=600、output=60、total=660、cached=120且不额外加到total。首次A为110，全部后为660；重扫、重启、移动后仍660。预期由给定增量手工相加，不能用产品解析器生成。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺已验证原生日志生成器、原生采集UI与结果读取绑定、清理游标/库程序；不可用scripts/test_data.py的标准化记录冒充Codex原始日志；SQL不得直接插入用量表来证明采集。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。

## E2E-TM003-002 · 累计值、重复事件、分支和未知格式

**验收：** `AC-TM003-002`，不直接逐行累加最近用量；继承历史不重复；不可核实数据有诊断且不污染可信总量。

**前置/数据：** 数据集 `codex_raw`；codex_raw 规划独立分组：累计input/output 100/10→150/15，重复最后一条；另开启有明确新会话身份的重置累计30/3；分支复制前序历史后新增20/2。再附一条未知结构与一条无法解释的累计回退。版本、事件/分支语义仍需实际fixture证实。

**步骤：**

1. 将前两条累计记录依次追加，通过App真实读取；重复追加相同token_count并重新扫描。
2. 追加有明确新会话身份的累计重置记录，检查不会产生负增量或丢掉新会话用量。
3. 创建带继承关系的分支日志，含复制历史及一条新增调用；扫描原分支和新分支。
4. 追加未知格式及无法核实来源的回退记录，查看诊断并核对可信记录没有被覆盖。

**独立预期：** 可确认的新用量为150/15+30/3+20/2，即input=200、output=20、total=220；重复累计和继承历史贡献0新增量。未知/无法核实回退须单独诊断，不作为0值成功事件，也不污染220可信总量。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺能表达累计/新会话/继承关系的已验证raw fixture与独立expected；未知格式降级UI/测试未实现；采集不可由SQL插入替代。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。

## E2E-TM003-003 · 半行完成与源日志清理

**验收：** `AC-TM003-003`，不吞掉随后完整事件；已采集统计保留；缺失历史有提示。

**前置/数据：** 数据集 `codex_raw`；codex_raw 规划完整调用A=100/10、待分两次写入调用B=50/5；当前已导入历史覆盖范围另有边界标记。原始字节拆分与文件清理程序未实现。

**步骤：**

1. 追加完整A，等待App采集并记录游标。
2. 只写B原始JSONL的一部分且不完成行，触发扫描；核对未将半行消费为有效事件。
3. 补全B剩余字节和换行，再触发扫描与重启；检查B进入一次。
4. 删除仅fixture拥有的旧源文件，启动重新扫描并查询已落库记录及历史覆盖提示。

**独立预期：** 半行时只有A、total=110；补全后A+B共2条、total=165，重启不重计。源文件删除不删除已采集统计，早于可证明覆盖范围的历史显示缺失，不能以0表示。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺字节级追加/归属校验清理器、raw版本样例、游标观测与原生绑定；无可直接执行造数SQL。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。

## E2E-TM003-004 · 重新授权后的去重

**验收：** `AC-TM003-004`，恢复后已有源事件不重复计数，新事件仅计一次，结果与独立预期一致。

**前置/数据：** 数据集 `codex_raw`；TM-002权限恢复已可运行；Codex目录含已采集A=100/10、B=200/20。撤销期间追加C=300/30，重新授权后还重放A。codex_raw 与system_permissions跨fixture绑定待实现。

**步骤：**

1. 从App授权目录并确认已采集A/B，记录唯一事件和累计值。
2. 撤销该测试目录权限，在无权阶段追加C及重复A；触发补扫。
3. 从App重新授权相同目录，等待恢复扫描。
4. 手动刷新并重启，再核对客户端持久记录和产品显示。

**独立预期：** 撤销期间不读取；恢复前total=330，恢复后唯一A/B/C共3条、total=660；重放A贡献0；刷新和重启后保持660。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺权限/日志联合生成及重置程序、原生重新授权和去重断言；不能只复用TM-002授权状态通过。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。
