## E2E-TM004-001 · 主会话与子代理归属

**验收：** `AC-TM004-001`，每次实际调用计一次，子代理包含在正确归属。

**前置/数据：** 数据集 `claude_raw`；依赖TM-002/003；claude_raw 须注明已验证Claude Code版本。规划主调用M=100/10与子代理S=200/20，同属用户alice/项目A，具有明确父子关系且模型字段可不同。

**步骤：**

1. 向授权主会话目录追加M，由真实App读取并确认归属。
2. 向对应子代理目录追加S，等待事件变化或补扫。
3. 重新扫描主/子文件并退出App重启。
4. 核对每个调用的源身份、所属账号/项目、子代理标志及总量。

**独立预期：** M与S各入账一次，共input300、output30、total330；S计入正确父项目，不因主会话引用而再计一次。模型明细保留各自原始可识别模型。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺有来源的claude_raw生成器、父子关系oracle、真实采集/诊断UI；不得直接SQL灌入规范化事件作为日志验收。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。

## E2E-TM004-002 · fork历史、消息改写与半写入

**验收：** `AC-TM004-002`，继承历史不重复入账，未完整事件等待后续读取。

**前置/数据：** 数据集 `claude_raw`；规划原会话M=100/10，fork继承M但消息ID变化；分支新增N=50/5，最后调用P=20/2分段写入；同一片段重复出现。实际继承识别字段需由版本化raw证据确认。

**步骤：**

1. 读取原会话M，再增加复制历史且有继承线索的fork日志。
2. 在fork追加N，重复写同一片段并扫描；核对继承及真实新增量。
3. 仅写P半行，触发扫描；随后补齐剩余行。
4. 重启App，对原会话及fork全部重扫，核对事件归属和数量。

**独立预期：** 继承历史虽改消息ID仍不重复；M+N阶段total165，半写入不增加，完整P后total187，共3次实际调用；重启不再增加。不能只以消息ID相等作为去重预期。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺可验证的fork/ID改写样例、半行程序和继承oracle；结构未核实时为BLOCKED，不能用编造厂商字段称支持。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。

## E2E-TM004-003 · 支持版本与未知usage降级

**验收：** `AC-TM004-003`，支持版本结果准确；未知版本或缺字段明确降级，不能伪造零用量。

**前置/数据：** 数据集 `claude_raw`；为每个拟声明支持版本准备原生样例及独立expected，例如完整调用100/10；另准备未知结构版本和缺usage的事件，后两者不用0填充。当前无已验证版本样例。

**步骤：**

1. 逐个从空库加载已声明版本样例，通过App采集；保存版本、fixture与结果对应关系。
2. 添加未知版本记录，刷新并打开诊断。
3. 添加有会话但缺usage的事件，核对该记录的缺失状态。
4. 重扫和重启，比较可信总量、降级数量和UI提示，检查无崩溃。

**独立预期：** 支持版本各与其独立数字相等；未知版本/缺usage明确显示未识别或缺失，不能当作有效零用量，也不覆盖已知调用110。支持列表必须由真实结果决定。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺厂商版本证据、版本化raw/缺字段生成器、解析器及原生诊断入口；SQL不适合替代版本解析测试。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。

## E2E-TM004-004 · 主/子代理重新授权去重

**验收：** `AC-TM004-004`，恢复后主会话、子代理与继承历史不重复计数，新调用仅计一次。

**前置/数据：** 数据集 `claude_raw`；初始主M=100/10、子S=200/20及继承M的fork均已扫描；失权期间子代理追加N=50/5。claude_raw 和权限状态联合fixture尚未实现。

**步骤：**

1. 从App授权主/子目录，记录M/S及fork的可信总量。
2. 撤销测试目录权限，追加N并复制一份旧子代理日志。
3. 通过App重新授权对应目录，恢复主、子、fork扫描。
4. 重启后再扫描一次，核对调用身份、父项目与总量。

**独立预期：** 恢复前total330，恢复后唯一M/S/N共3调用、total385；继承M和复制S均不重复；读取失败期间不生成成功零值。

**绑定/证据/状态：** `planned`；`automated_test=null`，未有原生函数绑定和执行证据。按 SOP-010/011 补齐后由 SOP-014 执行；缺项：缺联合授权恢复/原生日志fixture、目录隔离清理和自动UI绑定；不能以TM-002单独通过代替。 预期证据包括当前release_id/候选SHA、输入与expected摘要、原始原生结果、逐步断言/必要截图、数据/故障恢复与清理记录；当前这些产品证据尚不存在。
