# 架构与实现边界

状态：全产品架构约定；TM-001 的 App、认证服务和原生 runner 已建立并正在验收，其余功能按路线图迭代。实际证据见[当前状态](../status.md)。

## 组成

- `apps/macos/`：已建立 SwiftUI 账号界面、受保护本地文件凭据、Sparkle 与 XCUITest target；文件凭据自动登录和同机回环更新已在 CI 36674477502 的两台 macOS15 测试机通过六例开发回归，最终内部包需在本轮候选上另验。旧 Keychain 凭据不迁移。日志适配器、本地 SQLite、离线队列和同步客户端待后续功能实现。
- `server/`：FastAPI 认证、角色权限、账号管理、审计及 SQLAlchemy/Alembic 数据库；用量接收与统计待后续实现。
- `scripts/`：文档/追踪检查、真实原生测试编排与原始结果复核、发布候选检查。
- `tests/`：功能与验收清单、隔离账号和更新数据程序、服务端与治理回归；原生用例位于 App 的 UI test target，真实工具日志 fixture 随采集功能增加。

## 数据流

授权目录 → 来源适配器 → 标准化/去重 → 本地 SQLite 与待同步队列 → HTTPS 服务端 → 团队统计。

客户端数据库持续保留；v0.1.0 服务端回归库为 `database/test/test.db`，供 Codex 造数和重置；用户库为 `database/production/production.db`，只在首次建库预置管理员，后续启动不得覆盖账号。生产服务保持单实例并定期备份。MySQL 在后续迁移版本单独设计和验收。客户端不直接连接服务端数据库。

更新源服务与API服务是两个独立进程/端口：API默认49176，更新源默认49177。用户此Mac上运行App时两个回环地址指用户此Mac；GitHub `macos-15` 与 `macos-15-intel` 各自在自己的Mac运行App、API和更新源，彼此及用户本机均不共用 `127.0.0.1`。配置页 `configuration.open/api-url/update-url/save/reset-defaults/cancel/error/status` 保存显式覆盖；恢复默认删除两项覆盖。已登录或有待确认退出时不得更改API/总恢复默认，更新期间不得更改更新URL。更改URL不更换固化的EdDSA公钥，更新URL与选中下载URL均须做HTTP回环/非回环HTTPS校验。早期候选曾使用公网源；同机回环方案已由 CI 36674477502 验证。该结果只绑定其被测候选，不能直接作为新候选或最终DMG的通过证据。

v0.1.0 App 的首次默认服务地址为 `http://127.0.0.1:49176`，登录页可修改。正式构建对本机回环地址允许明文 HTTP；非回环地址仅允许 HTTPS，TLS 验证与重定向拒绝仍有效。App 区分内置默认值与用户显式覆盖；跨启动保存覆盖值，换服务时不得把旧服务 token 发给新服务。生产服务器确定后，升级包可以更新内置 HTTPS 默认值，只有未覆盖默认值的安装随之迁移；手动覆盖保持原值。该迁移须在对应版本验证，不视为 v0.1.0 已实现。

登录页默认开启“在此设备上自动登录”，可关闭；服务器签发随机、可撤销、固定30天到期且不滑动的 token，客户端只在开启时持久化，不保存密码。生产文件位于当前用户 `~/Library/Application Support/TokenMeter/credentials`，目录0700、文件0600、当前uid、拒绝symlink、原子写并按规范化API origin隔离；这些权限不阻止同uid进程读取或主动复制token。启动必须经 `/v1/me` 验证才显示已登录，关闭时仅内存会话、重启回登录。旧 Keychain 凭据不迁移，预览用户首次需重新登录。UITESTING 使用每例临时路径，两个升级构建写入同一路径，不能把带测试路径的 App 打成用户可登录预览 DMG。

统一 `/v1` API 覆盖登录、设备、批量用量、统计、导出、管理。成员身份由服务器从认证上下文确定，不接受客户端任意指定归属。数据记录携带来源/版本、稳定事件标识、时间、模型、Token 分类、项目、价格版本和质量状态。

## 必须通过测试证明的边界

- 来源适配器只读取用量和去重元数据，不能把原始 transcript 当成上传 payload。
- 累计差值、重复事件、缓存/推理子项、跨文件移动、分支继承、子代理都可能影响总量。按已验证的工具版本实现，不假定日志 schema 永久稳定。
- 同一源事件重复提交不增加统计；离线队列持久化和确认删除需在数据库事务中完成。
- 未知格式或无法可靠去重的数据进入诊断，不能静默算作零或正确用量。
- 测试 fixture 的预期由独立规格维护，不能运行生产统计代码来生成 expected 后再用同一代码验证自己。
- 真实 E2E 运行原生 App、真实服务端和隔离数据库；只在日志和外部更新服务器边界使用可控数据/服务。
- 开发迭代的 UITESTING 构建允许注入专属目录和本地服务地址；隔离参数仅测试构建可用。最终内部包测试在一次性GitHub Mac账号取得标准凭据目录/UserDefaults的所有权后运行生产App，测试参数只交给独立测试runner，不注入生产App。生产包不得暴露绕过认证或造数入口。

## 升级与运维

最小更新器是 0.1.0 的交付基础，默认从运行App的同机 `http://127.0.0.1:49177/appcast.xml` 发现更新，配置页允许合法地址覆盖并可恢复内置默认；HTTP仅限精确回环主机，非回环更新地址必须HTTPS。保留点击安装、固定EdDSA公钥、`SUVerifyUpdateBeforeExtraction`、无效包拒绝和失败保持原版；0.10.0 完善更新设置、变更说明和恢复体验。首个候选使用隔离源中的受控高版本测试包验证自身更新器，后续候选从上一内部稳定版验证实际更新。开发签名包只用于开发验证；最终内部分发包必须单独通过 DMG 安装升级、完整原生矩阵和机器门禁，公开分发另需 Developer ID、公证。

客户端和服务器迁移均有版本、事务策略、备份与恢复验证。数据库升级失败时不继续写入半迁移状态。生产升级先部署兼容的服务端，再发布客户端安装包/appcast；旧客户端兼容性属于发布 E2E。

签名、发布凭据存放在受控环境，不进入 Git、fixture 或报告。应用仅展示估算费用；价格来源与生效时间可追溯。
