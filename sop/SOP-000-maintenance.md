# SOP-000 规范维护

**修订：** 6　**状态：** baselined　**适用：** all

## 目的与范围

为新增或改变的工作定义可执行规则，由SOP管理会话维护`sop/`下的SOP与索引，并把受影响的非SOP文档交给文档会话。本 SOP 也约束自身修改。

## 触发条件

用户改变流程要求、现有 SOP 缺步骤/判据、规范冲突，或需要迁移 SOP 编号和位置。

## 前置条件

读取当前[工作索引](README.md)、[文档规范](../docs/standards/documentation.md)及受影响流程；明确规则来源和当前 release_id。其他会话先向「SOP」管理会话（thread ID `01a0f5a5-63f7-76b0-aa53-ac6befec91ef`）报告修订需求，由该会话执行本 SOP。非SOP文档的唯一编写者为「文档」会话（thread ID `01a0f14b-0888-7e93-bb85-a76b419f2ba7`）；迁移前按旧有效 SOP 执行，迁移后采用本目录。

## 输入

已确认的用户要求或其他会话的修订通知、旧SOP/规范/模板、工作步骤清单、依赖引用、版本档案和 `docs/catalog.json`；需要非SOP同步时附目标文件、具体内容与依据、适用版本、代码或原始证据、紧急依赖。

## 执行步骤

1. 管理会话核对用户要求或通知中的规则来源、缺口、依据和受影响流程；按具体工作列出触发、输入、产出、成功判据和前后步骤，查找缺口及重复定义。修订完成后通知提出需求的会话，使其按新规范恢复依赖步骤。
   涉及 `127.0.0.1`、`localhost` 或 `::1` 时，明确是哪台机器、哪个进程提供服务；本机证据和远端 runner 证据分别记录，不以同一字符串推断同一服务。
2. 确认需要新增步骤还是修订现有步骤，保持已建立的编号/名称稳定；必要迁移记录旧→新映射与原因。
3. 先更新索引，再逐份写十个固定章节；SOP管理会话只直接编辑`sop/`中的SOP与索引。执行命令必须存在，未来能力注明前置缺失，不伪造命令。
4. 对受影响的非SOP规范、模板、文档目录、版本记录、Changelog、AGENTS或总表，向文档会话发送目标文件、具体改动、依据、版本、相关代码或原始证据及紧急依赖，由该会话按SOP-024编写、检查和提供提交/证据；SOP管理会话核对其与SOP文本一致并通知总控集成，不自行改写非SOP文件。已经完成但未集成的非SOP改动保留原提交和证据，完整交接文档会话，不丢弃或悄悄移除。删除当前SOP入口中的过期路由，保留历史提交可查。
5. SOP编制中执行 `python3 scripts/check_docs.py --mode structure`，核对引用、步骤顺序、循环依赖和是否误把计划写成通过；文档会话完成非SOP同步后核对两份提交及目录、版本记录和Changelog。全部受影响计划形成且必要文档已同步后，按 SOP-008 对整合候选执行严格基线检查及 `python3 scripts/quality_gate.py check`；不要求未编写的后序计划提前通过基线。SOP-only 分支检查PASS可交总控先行整合，但不得把未完成的非SOP同步记为本次完整维护PASS。

## 输出

完整 SOP 索引、独立工作 SOP、向文档会话交接的非SOP变更清单及其提交/检查记录；整合后关联的规范、模板和目录。

## 成功与失败判据

成功须覆盖本次所有工作，SOP与必要非SOP文档由各自负责会话完成、集成后结构/引用检查通过，后续执行者无需猜关键前提。文档会话尚未完成依赖同步时只记录SOP部分完成和具体阻断；缺步骤、断链、冲突或虚构命令为失败；产品执行器仍缺失不能由规范更新解除 BLOCKED。

## 异常恢复

保留失败清单，修正对应规范后重查。迁移未完成时记录明确边界，禁止同时把相互矛盾的旧/新入口作为当前标准。

## 证据位置

文档会话在当前 `releases/<release_id>/06-iteration-record.md` 记录规则来源、映射、决定及实际检查命令/结果；SOP分支diff、交接消息、文档提交和目录diff作为可追踪输入。
