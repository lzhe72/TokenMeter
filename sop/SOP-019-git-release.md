# SOP-019 Git 版本追踪

**修订：** 10　**状态：** baselined　**适用：** all

## 目的与范围

由项目总控按版本依赖将各需求分支逐个集成到本地`master`，为每个版本固定不可变SHA/tree并执行该版本最终包门禁；合格的本机稳定包可先按SOP-020归档，供下一版本真实升级。全部目标版本完成后，总控统一走受保护远端`master`与逐版Tag登记。安装包及原始证据不上传Git。

## 触发条件

需求分支达到本地里程碑集成条件；某版本通过正式本机门禁、需要成为下一版本稳定升级源；或全部目标版本完成、需要统一远端源码登记与正式Tag。PR只在远端策略要求时作为受控替代路径。

## 前置条件

用户已授权总控自主整合、最终统一远端推送和适用门禁后的本机发行。分支具有对应release_id、文档基线和适用检查结果；本地与远端`master`的实际状态可核对。每个正式产品版本须在其**本地master固定里程碑提交**上由固定程序完成本轮与此前已交付功能的完整产品E2E、SOP-017/018最终包门禁，再按SOP-020形成可供后续升级的本机稳定包；远端源码登记不作为本机稳定包的前置，但在全部目标版本完成前保持待办。正式Tag仍须本地通行证及最终远端读回。仅规范及其必要文档附件的独立分支可在SOP-008结构、基线和治理检查通过后先行并入源码`master`，但不得记为产品E2E、发布PASS、通行证或Tag；后续产品候选须以新基线完成完整门禁。2026-10-01用户再次确认Git仅用于源码版本管理、本机承担产品测试，旧Actions必需检查已移除；其余远端保护仍须满足。未提交的用户改动不得覆盖或带入整合。

## 输入

按版本顺序的需求分支及提交、版本档案与Changelog、`origin/master`、每个本地`master`里程碑SHA/tree、适用检查与原始E2E/包/通行证/本机稳定归档摘要、最终整合候选SHA/tree；远端保护规则及2026-10-01迁移快照、工作流触发与适用用户决定。

## 执行步骤

1. 由总控运行 `git status --short --branch`、`git remote -v`、`git ls-remote --heads origin master`，核对当前分支、远端及未提交改动。以只读 GitHub API 核对 `master` 的 PR、required checks（名称、预期 App、strict）、管理员执行、强推/删除规则，并核对工作流实际触发条件；保存带时间的原始规则快照，不能从旧记录推断当前保护。保存各需求分支提交和 release_id；只将源码、文档、配置、测试及数据程序纳入 Git。DMG/ZIP、数据库、密钥、`node_modules`、原始报告和通行证保留本机忽略目录。
2. 每个需求分支先按其任务和既定TC完成适用基础检查及开发阶段回归，记录失败与阻断。总控先以`git fetch origin master`获取远端状态，在干净检出中执行`git switch master`、`git merge --ff-only origin/master`；若远端与本地已分叉则停止查明，不覆盖本地独有提交、用户改动或强制重置。按TM001→TM002→TM003→TM004→TM005的依赖顺序，在上一版本的本机稳定包及本版前置条件实际成立后逐支执行`git merge --no-ff <需求分支>`，遇冲突按原需求/用例修正并保存整合记录。各需求分支不各自推送或合并远端`master`；最终统一远端推送前，所有本地里程碑提交须沿同一`master`祖先链保留，不rebase或丢弃已发行的本机来源提交。缺上一稳定包时可继续不依赖它的开发准备，但下一版本正式升级/E2E/发行门禁保持BLOCKED。
3. **每个版本里程碑**整合后记录`git rev-parse master`、`git rev-parse 'master^{tree}'`、父提交、release_id和干净工作树状态，冻结该提交及适用文档/用例/依赖清单。对这个实际本地`master`里程碑执行SOP-008/013/014的适用检查与本版及此前已交付功能完整E2E；正式本机发行继续SOP-017/018，从同一最终DMG安装验证，PASS后按SOP-020独占归档正式稳定包，记录本机通行证、原包摘要与“远端源码登记待办”。只有这一真实稳定包可供下一版本的正式升级用例；当前未通过门禁的开发/候选包和首版受控101均不可替代。后续合并不得改写先前里程碑或将其旧证据借给新版本；前一里程碑可在独立干净检出按原SHA/tree复核原件。独立纯规范分支只做SOP-000/008/024的结构、基线、治理和引用检查，明确`release_eligible=false`，不出产品通行证或Tag。分支单独PASS、旧候选报告、PR状态或仅tree相似不能替代该里程碑完整验收；任何产品整合、冲突修复、源码/依赖/包输入变化均形成相应版本的新候选并重新核验。
4. 全部目标版本均按步骤3形成本机门禁和稳定包后，才由总控启动**一次最终远端`master`源码整合**。再次读取远端保护并核对`origin/master`是否前进；2026-10-01远端`master`已移除三项旧Actions required checks，仍强制PR、管理员执行和对话解决，禁止强推/删除，以每次实际读回为准。若允许直推且要求实际满足，普通快进推送并读回SHA；当前强制PR则走第5步。远端未完成期间，逐版本机稳定包的源码登记和正式Tag明确为待办，不写远端PASS；不得把本机PASS冒充远端检查、强推、管理员绕过、删除保护、伪造或手写PASS。保护变化无法满足时远端登记BLOCKED，已取得的本机产品原件与结论单独保留。
5. 对当前强制PR规则，以**最后一个已测本地`master`整合候选**建立同一条远端PR来源分支，保留按版本顺序的全部本地里程碑祖先提交及最终SHA/tree；核对PR base/head、实际保护和远端`master`未前进。只允许保留提交祖先链的合并方式，不得用squash/rebase使已归档稳定包的来源提交消失；若远端策略无法保留，远端登记BLOCKED并核对可行路线。PR审查与对话解决等要求须满足；新增required checks逐项核对名称、App来源、结论及strict基线，不能用本机报告或手写状态替代。GitHub Actions完整多环境测试只在用户明确要求时设计和启动。新保护与本机流程冲突时保存快照和影响，按SOP-000及明确用户决定修订，不私自临时关闭保护。
6. 合并PR前逐版复核本地里程碑仍为最终候选的祖先，各版本原始门禁对应未变的SHA/tree、包输入及正式本机DMG，并复核最后候选的完整产品门禁。远端base前进或PR改动最后候选内容时形成新本地最终候选，按受影响范围重跑完整门禁；以前已归档的本机稳定原包及其不可变来源不回写或冒用。按保护规则合并后读回远端`master`SHA/tree，与最后被测候选建立严格tree映射；再逐版验证原里程碑提交仍可从远端`master`追溯、每份本机通行证/归档的SHA/tree及原包摘要与该提交精确一致。任一版本来源消失、内容不符或无法证明一致，远端源码登记BLOCKED，不补Tag、不把本机包伪称远端已登记。记录不同的远端合并SHA，不能写成原被测SHA；各需求分支不得绕开本地顺序分别在远端合并。
7. 远端步骤6全部核对通过后，总控按版本顺序为每个已取得本机SOP-018 PASS与SOP-020稳定归档的release_id创建annotated源码Tag，精确指向其远端可追溯的本地里程碑提交，逐个读回Tag SHA和目标；不能用最终第五版的树替代前版Tag。Tag只记录源码，不独立授予本机发行资格，不创建GitHub Release或上传包/原始证据。Tag已存在、目标冲突或来源不符即停止该版及后续远端登记，不移动已正式登记Tag。首次未取得本机通行证的候选不能Tag。
8. 在本机`.local/git-sync/`、各版本06和本地发行记录逐版保存需求分支→本地里程碑SHA/tree→门禁run/package/passport→020稳定原包/归档→远端待办→最终保护快照/PR/读回→逐版远端可追溯提交与Tag的映射，以及实际命令、退出码；未执行的阶段只记待办，不写PASS。

## 输出

逐版本地`master`里程碑及门禁/稳定包记录、最终远端`master`读回与逐版源码Tag映射；本地发行索引分别显示已完成和远端待办。

## 成功与失败判据

纯规范分支本地整合成功要求范围仅含SOP及使其可执行的规范附件，SOP-008结构/基线和治理检查PASS、本地提交与已检查树严格对应，并记录产品`release_eligible=false`；远端阶段另须满足实际保护并读回对应来源。逐版本地稳定成功要求该版本里程碑及此前已交付功能的适用完整E2E、最终包与018门禁真实PASS，020原包/通行证独占归档并读回；远端仍可记待办，不能冒充远端PASS。最终远端源码登记成功另要求全部目标版本按顺序在本地`master`祖先链中、各版稳定原件有效、最后候选完整门禁PASS；快进推送读回SHA一致，强制PR须有第6步最终tree映射和逐版祖先/原件映射。正式Tag按第7步逐版核对。任一适用检查FAIL/BLOCKED、无法解释的远端差异、缺失的前版稳定源、未清理工作树、缺证据或推送拒绝均不得记相应阶段完成。

## 异常恢复

保留原始失败、本机稳定原件和已发生的远端事实；不强推、改写已发行里程碑、移动Tag或修改门禁结果。重新核对远端与本地变更，形成新的受影响版本/最终整合候选并重跑其完整产品门禁；保护新增无法满足的要求时远端阶段保持BLOCKED，按第5步处理，不自行降低要求。

本机 `.local/git-sync/`、`releases/<release_id>/06-iteration-record.md`、原始测试/门禁目录和本地发行档案。
