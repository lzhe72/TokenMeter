# SOP-019 Git 发布

**修订：** 2　**状态：** baselined　**适用：** all

## 目的与范围

将同一版本的源码、文档、测试通行证和已验证产物固化为可查询的 Git 发布。

## 触发条件

候选取得有效发布通行证，且已有正式发布授权。

## 前置条件

正式 Tag 创建前，SOP-018 已针对确定候选 SHA 完整 PASS 并生成有效通行证；受保护发布任务和远端权限已配置，预期 tag/Release 不存在且候选提交/产物未改变。不得先建 Tag 以触发首次发布验证。

## 输入

release_id、通行证、候选 SHA、版本 manifest、Changelog、最终资产及目标 Git 远端。

## 执行步骤

1. 执行 python3 scripts/release_registry.py show 核对当前档案；如发布其他版本，使用 --release-id 指定实际编号，并核对返回编号。
2. 受保护发布任务消费候选 CI 生成的原通行证，重新核验受信运行身份、来源、签名产物摘要、对应 commit 和精确 Changelog 标题。若后续配置 Tag 触发，仅用于核对已经通过的发布，不补做或替代创建 Tag 前的候选门禁。
3. 仅创建与 release_id 完全相同的 annotated tag，指向通过验证的提交；创建同名 Git Release 并附原包、原报告和原通行证。
4. 检查远端 tag 指向、Release 名称、资产摘要与查询链；不能成功后再替换包或移动 tag。
5. 实际结果写入不可覆盖的发布记录，源文档不得为写入自身 SHA 而反复提交。当前尚未实现通行证签发和 Tag/Release 发布自动化，基础建设版无产品 PASS，不创建产品 tag。

## 输出

不可变 tag、同名 Release、已验证资产/报告/通行证和可查询发布关联。

## 成功与失败判据

所有标识、commit、资产与通行证一致且远端操作成功；单有 Git tag 或同名 JSON 不是发布通过证明。

## 异常恢复

部分失败时停止后续部署，保留已发生操作的事实并核验远端状态；不盲目重建已存在 tag/Release，不改写历史来掩盖失败。

## 证据位置

受保护发布任务日志、远端 tag/Release URL、资产摘要和版本查询结果；失败同样保留。
