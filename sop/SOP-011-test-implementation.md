# SOP-011 测试实现

**修订：** 1　**状态：** baselined　**适用：** all

## 目的与范围

将测试计划落实为可检测产品行为的真实自动化测试，并建立有效的失败基线。

## 触发条件

新功能开始实现前、扩展平台/日志兼容或缺陷需要新增永久回归时。

## 前置条件

SOP-006 的场景与独立预期明确，SOP-010 数据可用；原生测试所需环境经 SOP-009 确认。

## 输入

用例清单、数据程序、期望值、原生 App/服务接口、测试框架和证据合同。

## 执行步骤

1. 为场景创建实际测试入口，按需要分别实现单元/集成检查与原生 UI E2E；E2E 驱动真实 App、认证、服务和数据库。
2. 编写用户操作及可观察结果的断言，使用独立 expected；覆盖权限、失败、边界和数据恢复，不复刻生产逻辑作为答案。
3. 实现数据初始化、服务健康等待、UI 系统交互、超时、清理及原生报告采集；禁止固定延时掩盖竞态或仅以截图判通过。
4. 在尚未实现/未修复版本执行，确认失败来自目标行为而非缺环境、无法编译或空测试。
5. 把实际文件与测试身份绑定功能矩阵；进入 in_progress 前全部对应数据集 available，数据程序与测试入口真实存在。
6. 产品 runner 尚未实现时同步实现其执行与证据校验任务；空成功脚本不能解除当前 BLOCKED。

## 输出

真实测试、数据/测试绑定、有效失败证据及自动执行/清理入口。

## 成功与失败判据

测试确实发现预期缺失行为、能生成原生可解析结果并匹配用例 ID；环境失败不算有效失败基线。缺执行器明确 BLOCKED，不能宣称测试完成。

## 异常恢复

测试不稳定先检查等待条件、隔离和数据归属；修根因，不以跳过、xfail、重复重试或删断言取绿。

## 证据位置

源码中的测试文件和矩阵，运行产生的原生报告、初始失败原因、fixture 摘要与环境。
