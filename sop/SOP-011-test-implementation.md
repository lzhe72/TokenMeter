# SOP-011 测试实现

**修订：** 8　**状态：** baselined　**适用：** all

## 目的与范围

将验收场景实现为真实Electron产品E2E与必要基础回归。

## 触发条件

新增功能、缺陷或客户端迁移。

## 前置条件

006/010数据设计与可运行009骨架；源码可先编写，业务红测必须真实运行。

## 输入

详细用例、固定ID、fixture、真实App/服务。

## 执行步骤

1. 测试必须是仓库中固化、可按TC编号重复执行的代码。输入、动作、预期和断言在运行前确定；AI只能调用这些代码并分析原始结果，不能以临场操作、看图判断或手填结果代替测试。缺自动化绑定或缺可执行判据为BLOCKED。 每条绑定记录代码文件、测试名称、数据生成/重置程序和独立命令。

2. 先逐条读取已基线的 TASK→TC 及其独立预期，再编写数据准备、测试动作和断言；保留 TM001 六个 E2E 场景组 ID，后续版本另登记自身稳定场景组，组内每个 TC/参数变体独立记录。每步实际动作、预期/实测值和原始证据须按[执行记录合同](../docs/templates/test-execution.md)采集，未建立逐 TC 绑定不能用大场景 PASS 覆盖。冻结候选时由固定代码核对 `tests/test_cases.json`、变体清单、功能矩阵与各来源 release 的版本计划，求目标版本和此前已交付功能的精确父TC/变体/辅助/聚合/审计并集；来源版本、ID、程序绑定及清单摘要随原件保存，未来 planned 项不得混入。

3. TM001 沿用六例稳定ID和UI交互/独立预期；后续版本按自身已基线的场景组和TC绑定增加执行入口，使用Playwright Electron启动真实构建或安装App，禁止改测浏览器页面替代桌面产品。TM001 的 `scripts/local_e2e.py`、`scripts/granular_e2e.py` 等计划入口只有进入候选且真实运行后才能证明其执行范围；它们若不能按冻结并集逐来源执行并记录 TM002/003 及后续新增项，最终跨版本门禁保持BLOCKED，须先实现并负测扩展入口。
4. 逐条编写UI操作、服务/SQLite旁证和边界断言；测试不得通过route、IPC stub、写用户表或修改App状态生成成功。
5. 修复先保留稳定失败，再改实现；缺环境或入口不称业务失败。迁移保留旧测试为历史，新的Electron绑定就绪后同步矩阵/manifest。
6. 为最终包采用executablePath指向从原DMG复制的App，记录进程路径与哈希，显式chromiumSandbox；业务用例不能靠关安全配置取绿。
7. 004必须观察实际自主升级与重启，测试只重连新进程。系统原生弹窗不可用DOM stub证明，签名/Gatekeeper另记实际系统结果。
8. 记录原始Playwright JSON、trace、截图、断言/服务日志和清理；账号/凭据仅合成且证据本地0700。

## 输出

真实测试程序、失败基线、数据/SOP/矩阵绑定。

## 成功与失败判据

能检测错误业务行为才有意义；零用例、mock成功或无法复现视为未完成。

## 异常恢复

失败分类定位，保留首个证据，不删断言或多次重试取绿。

## 证据位置

计划中的`apps/desktop/e2e/tm001.spec.ts`与`scripts/local_e2e.py`、本机`.local`原始证据、版本06。TM001六组聚合场景的开发运行与各来源 release 新增精细TC逐项绑定分别记录；程序尚未进入最终整合树或跨版本扩展未实际落地时保留BLOCKED。
