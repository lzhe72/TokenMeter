# SOP 工作入口

先按工作选择 SOP，再读取前置条件、输入和步骤。每一步都需要 SOP；找不到合适流程时先执行 SOP-000。SOP 按工作划分，同一流程可由 Codex、其他 agent 或开发者执行，不按角色复制。

本目录为当前唯一 SOP 入口；编号和名称从本基线起保持稳定。历史版本按对应提交中的旧定义查询。各文件修订号见下表，状态 `baselined`、适用范围 `all`，表示流程定义可用，不表示产品或执行环境已经通过验收。

**维护分工：** 任何会话发现需要新增、修改或删除 SOP（含本索引）时，先将具体缺口、依据和受影响流程通知 TokenMeter 的「SOP」管理会话（thread ID `01a0f5a5-63f7-76b0-aa53-ac6befec91ef`），由该会话统一修改 `sop/` 下的文件。所有非 SOP 文档（含 AGENTS、docs、releases、Changelog、总表及文档目录）的新增、修改、删除由「文档」会话（thread ID `01a0f14b-0888-7e93-bb85-a76b419f2ba7`）统一完成；其他会话把目标文件、具体内容与依据、版本、原始证据和紧急依赖交给它。SOP 修订所需的非 SOP 同步也先交文档会话，双方分别提交并由总控集成核对。依赖修订的步骤在 SOP 与所需文档同步前保持阻断；其他不依赖步骤可继续。

## 需求阶段的任务与用例

**先写需求和功能点，再拆具体开发任务，基于任务逐项设计测试用例，形成基线后开发，最后按既定用例测试并记录。** 003负责具体TASK，006负责逐条TC，008检查覆盖；整版尚draft时仅允许008核准且不依赖未决项的明确TASK/TC开发切片进入实现，其余目标原样保留。011把已设计的用例编写为程序，不能等实现后才设计测试。根目录`TEST_CASES.md`随对应产品分支的用例基线集成；在该文件及程序进入最终整合树前，依赖它们的产品验收保持BLOCKED。详细规则见[用例规范](../docs/standards/test-cases.md)。

## 常用路线

- **新增功能**：001→002→003→004→005→006→007→008（整版或独立开发切片）→009（工程骨架）→010→011（真实业务失败基线）→012→013→014（本功能固定TC真实回归）；有数据迁移时调用016。功能结果如实记录，源码按019顺序本地集成并最终远端登记。开发阶段的完整跨需求门禁、018/020和正式Tag均未运行；只有用户另行明确启动正式对外发布时才走发布路线。
- **修复问题**：015先收集复现；新版本经001–008建立修复基线，再完成010/011的失败回归、012/015修复、013→014受影响的固定TC回归。正式发布时仍须重跑最终候选完整并集。
- **准备发布（正式版）**：收到用户明确发布指令后，019固定最终本地候选SHA/tree→008/013及014对最终候选一次执行全部目标和已交付功能的精确并集→017原包、安装与适用真实升级→018 PASS→020归档正式稳定DMG→019登记正式Tag与远端来源映射→022。没有上一实际稳定包时按已基线首发升级用例验证；若既定用例必须依赖不存在的稳定源，则BLOCKED，先修订基线，不能拿开发包冒充。已有开发回归不能替代最终候选门禁；失败转015/021。
- **多会话保存与集成源码**：每个需求在独立worktree的命名分支提交干净源码→019核对并快进推送同名远端功能分支、读回SHA/tree；总控按TM001→TM005在本地master集成并保存里程碑，记录各功能固定TC的真实PASS/FAIL/BLOCKED/NOT_RUN，可快进备份单一远端integration镜像分支；全部需求源码完成后遵守远端master保护，统一推送或受控PR并读回。源码登记不以每版完整E2E、018/020为前置，也不授予发行资格；正式Tag等待正式发布。独立纯规范分支执行文档/治理检查，不产生产品PASS。
- **维护文档**：编制中024→structure检查→返回原步骤；新增/改变规范先走000。001–007全部完成或已有基线修订整合完毕后，才进入008的严格baseline与质量检查。若改变产品行为、测试或发布配置，开发阶段执行受影响固定TC回归；正式发布阶段执行最终完整门禁，不能按纯文档变更放行产品。

## 固定测试代码

测试必须是仓库中固化、可按TC编号重复执行的代码。输入、动作、预期和断言在运行前确定；AI只能调用这些代码并分析原始结果，不能以临场操作、看图判断或手填结果代替测试。缺自动化绑定或缺可执行判据为BLOCKED。

## 当前边界与共同约束

- 用户2026-09-30最终决定：Electron + Playwright；本机完成开发、构建、完整测试、打包和发布。Git保存代码、文档、版本编号及追踪；DMG、更新包、原始报告和通行证只在本地按版本存储，不创建GitHub Release或上传安装包。
