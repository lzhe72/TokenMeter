# SOP 工作入口

先按工作选择 SOP，再读取前置条件、输入和步骤。每一步都需要 SOP；找不到合适流程时先执行 SOP-000。SOP 按工作划分，同一流程可由 Codex、其他 agent 或开发者执行，不按角色复制。

本目录为当前唯一 SOP 入口；编号和名称从本基线起保持稳定。历史版本按对应提交中的旧定义查询。各文件修订号见下表，状态 `baselined`、适用范围 `all`，表示流程定义可用，不表示产品或执行环境已经通过验收。

**维护分工：** 任何会话发现需要新增、修改或删除 SOP（含本索引）时，先将具体缺口、依据和受影响流程通知 TokenMeter 的「SOP」管理会话（thread ID `01a0f5a5-63f7-76b0-aa53-ac6befec91ef`）。由该会话按 SOP-000 统一完成修订并通知相关会话。依赖修订的步骤在规范同步前保持阻断；其他不依赖步骤可继续。

## 需求阶段的任务与用例

**先写需求和功能点，再拆具体开发任务，基于任务逐项设计测试用例，形成基线后开发，最后按既定用例测试并记录。** 003负责具体TASK，006负责逐条TC，008检查覆盖；011是把已设计的用例编写为程序，不能等实现后才设计测试。根目录[全部用例集合](../TEST_CASES.md)按功能、输入、预期、DB操作及类型导航；详细规则见[用例规范](../docs/standards/test-cases.md)。

## 常用路线

- **新增功能**：001→002→003→004→005→006→007→008→009（工程骨架）→010→011（真实业务失败基线）→012→013→014；有数据迁移时调用 016；需要发布再走 017→018→019→020→022→023。
- **修复问题**：015 先收集复现；新版本经 001–008 建立修复基线，再完成 010/011 的失败回归、012/015 修复、013→014。发布门禁与新功能相同。
- **准备发布**：核对 008 与候选一致→013/014→017→018→019→020→022。已有报告只能在提交、产物、数据和矩阵完全一致且仍有效时使用；失败转 015/021。
- **集成并推送源码**：核对需求分支与适用检查→019 在本地 master 集成→对最终整合树执行适用门禁→由总控统一快进推送远端 master→022 归档；产品测试与发布状态按实际结果保留。
- **维护文档**：编制中 024→structure 检查→返回原步骤；新增/改变规范先走 000。001–007 全部完成或已有基线修订整合完毕后，才进入 008 的严格 baseline 与质量检查。若改变产品行为、测试或发布配置，继续执行对应开发和完整门禁，不能按纯文档变更放行产品。

## 固定测试代码

测试必须是仓库中固化、可按TC编号重复执行的代码。输入、动作、预期和断言在运行前确定；AI只能调用这些代码并分析原始结果，不能以临场操作、看图判断或手填结果代替测试。缺自动化绑定或缺可执行判据为BLOCKED。

## 当前边界与共同约束

- 用户2026-09-30最终决定：Electron + Playwright；本机完成开发、构建、完整测试、打包和发布。Git保存代码、文档、版本编号及追踪；DMG、更新包、原始报告和通行证只在本地按版本存储，不创建GitHub Release或上传安装包。
- 安装包的可见入口为仓库根目录`dmg/<release_id>/`。开发/候选包文件名明确标记`NOT-RELEASED`；只有018 PASS后，020才在该目录创建正式原名DMG。原件和证据仍按run与候选独立存储，不用便捷副本替换被测原件。
- GitHub Actions完整测试仅在用户明确要求多环境时启动；不再由PR、push或默认发布触发。已有SwiftUI/XCUITest与CI结果属于历史实现/证据，不能替代Electron候选验收。
- 默认验收平台是当前真实本机macOS15 Intel。其他架构与系统只登记为未验证；构建成功不能作为跨平台通过。
- 先定义计划和SOP，再建立程序。入口尚未实现时明确BLOCKED，不要求安装完整Xcode，不手填PASS，不为发布删六例或放宽断言。
- 每次目标全部场景及此前已交付功能完整E2E。每个用例必须实际操作安装后的Electron App，使用真实服务和隔离SQLite；API/IPC mock与浏览器网页检查不能替代产品E2E。
- 本机默认地址指用户此电脑。测试profile、数据库、安装位置、服务端口须隔离，不覆盖用户生产库、凭据或现有App，不终止未知进程。
- `baselined`是文档状态；功能状态与PASS/FAIL/BLOCKED运行结果分别登记。本机机器门禁只在真实原始结果、候选SHA、产物和清单一致后签发通行证，不声称本机同uid可写文件具有不可篡改安全保证。
- 每一步按SOP记录输入、决定、实际输出/退出码、原始证据和下一步；未完成的依赖保持BLOCKED。明确用户指令优先，规则变更保留版本记录。

长期约束见[文档规范](../docs/standards/documentation.md)、[版本规范](../docs/standards/versioning.md)、[发布门禁](../docs/standards/release.md)。
