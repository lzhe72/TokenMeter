# SOP-017 安装包验证

**修订：** 1　**状态：** baselined　**适用：** all

## 目的与范围

验证最终签名产物的干净安装、启动、系统授权、升级和恢复，确保分发的就是测过的包。

## 触发条件

候选准备对外发布，或签名、安装器、更新器和支持平台发生变化。

## 前置条件

SOP-007 发布预案及 013/014 检查就绪；最终包、签名/公证能力、已登录 Mac 矩阵和原生自动化真实可用。

## 输入

候选源码、客户端/服务端产物、签名配置、支持矩阵、上一稳定包和升级/恢复用例。

## 执行步骤

1. 按真实构建/签名流程生成最终候选，记录源码与客户端/服务端 SHA256；校验 Developer ID、公证和适用的更新签名。
2. 在每个声明支持的系统/架构组合，用 UI 自动化安装实际签名包、首次启动并执行本次目标和历史功能。
3. 从上一公开稳定包安装测试数据，自动升级到候选，核对版本、配置、授权、本地/服务端数据和迁移；App 内更新交付后必须从实际 UI 验证发现、下载、安装和重启。
4. 首个没有上一稳定版的发布明确记录基线不存在，升级项只验证干净安装；从第二个发布开始不能跳过稳定版升级。
5. 测试下载中断、无效签名、安装/迁移失败和恢复，使用真实系统交互与原生断言；缺自动化路径保持 BLOCKED。
6. 归档签名和安装证据；测试后不得重新构建或修改安装包，再沿用原报告。

## 输出

最终产物摘要、签名/公证校验、各支持平台的原生安装/升级/恢复证据。

## 成功与失败判据

每个应测平台实际执行成功且报告绑定最终包才满足发布前提；编译目标、截图或测试版包结果不能替代真实签名包验证。

## 异常恢复

包验证失败停止推广，保留安装日志和现场；修复后生成新候选并重新完整验证。当前缺 App/签名/执行器时记录 BLOCKED。

## 证据位置

原生测试包、安装/系统交互附件、签名结果、前后版本和 SHA256，作为受保护 CI 产物关联 release_id/run_id。
