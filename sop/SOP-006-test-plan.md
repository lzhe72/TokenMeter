# SOP-006 测试计划

**修订：** 8　**状态：** baselined　**适用：** all

## 目的与范围

为每个验收条件同时定义用例、测试用户/数据程序、SOP、原生 E2E 和证据要求。

## 触发条件

开始功能/修复设计，或已有行为、数据和平台支持范围改变。

## 前置条件

SOP-002–005 的需求、设计和任务明确；阅读 [测试策略](../docs/testing/strategy.md)及 [执行规范](../docs/testing/execution.md)。

## 输入

验收条件、功能矩阵、数据集登记、历史回归与缺陷、支持平台和数据库。

## 执行步骤

1. 以具体开发任务为拆分单元：逐项枚举输入组合、前置状态、有序动作及每一步 UI/API/DB 预期，为每种情况分配 TC ID，回链 TASK 和 AC。错误密码、未知账号、空输入等分别列项。使用[用例模板](../docs/templates/test-case.md)，并按[规范](../docs/standards/test-cases.md)明确类型、SQL/DB操作、数据/重置和独立预期来源；缺产品决定为 baseline_pending，禁止从代码反推答案。维护根目录 TEST_CASES.md 总集合与详细用例入口；自动化和运行状态分别登记。

2. 对照独立 `tests/acceptance.json` 与需求定义表，将每条验收条件映射到正常、失败、权限及边界场景，使用稳定 E2E ID。要求“规格定义↔验收清单↔用例”双向齐全，不能通过删除必测用例缩小集合。
3. 定义本次应执行集合：目标全部场景加所有此前已交付功能；无关未来 planned 项不加入，目标不得降级状态规避。按真实能力在功能矩阵登记 `depends_on`；依赖必须已在本轮或更早版本交付，禁止早期验收依赖未来版本。跨功能场景放入依赖齐备的版本，并保留稳定追踪。
4. 定义角色、账号、日志/价格/故障数据、固定种子和参考时间，安排生成、真实账号导入、重置/清理程序。
5. 独立计算 expected，不能调用生产统计逻辑生成自身答案；明确原始日志版本与规范化样例的区别。
6. 写明 UI→真实服务/数据库的执行路径、系统交互、矩阵、命令、退出码、报告和失败处理；未实现绑定如实为 null。目录选择用例要驱动真实系统面板，并以受控测试目录核对 App 实际读取范围、取消、撤销及访问失效；不把这些结果标为系统沙盒授权或 TCC 撤销通过。重启恢复 TC 须验证私有加密 locator 的建立、跨重启恢复、撤销删除、密钥不可用或密文损坏时停读重选、账号/来源/根身份不匹配拒绝和日志/报告/同步无完整路径或密文。使用 macOS `safeStorage` 的 TM002/003/004 用例还须预设最终包实际 Keychain item 身份（service/account 或提供者等效标识）的独立证明、已有 item 时 BLOCKED、仅清理本次创建 item 的所有权判据；不能只凭隔离 profile 认定隔离。不能以临场注入路径代替系统选择，也不能用 UI 显示代替主进程读范围断言。
7. 在 `docs/testing/cases/README.md` 建立面向读者的总索引，每个功能使用带顺序前缀的独立文件。每个稳定 E2E ID 必须写出：验收条件、前置条件、账号/数据程序及 SQL、具体有序操作、独立预期、自动化绑定和 SOP、证据入口、状态与缺项。索引/JSON 中的一行摘要不能替代详细用例；规划项明确标 `planned`，缺程序、SQL、原始日志或 UI 入口时逐项说明，不编造可执行命令。
8. 登记 `tests/feature_matrix.json` 与 `tests/datasets.json`，确保详细文档与验收清单、矩阵的稳定 ID 一一对应，并将文档纳入 `docs/catalog.json` 和版本测试计划。验收清单中的 `data_requirements` 必须由绑定数据集的 `capabilities` 覆盖；基础数据 available 不代表覆盖扩展场景。规划数据不足时记录具体缺项，进入 in_progress 前必须补齐真实绑定、可用数据和所需能力。

## 输出

04-test-plan.md、逐功能详细用例与总索引、场景/数据登记、可被 Codex 执行的 SOP 合同和 E2E 实现任务。

## 成功与失败判据

本轮每条验收条件都有详细场景、数据、独立预期和自动执行方案，详细用例与机器清单一一对应；仅人工步骤、截图或 API 自测不能替代产品 E2E。未来用例可以保留明确缺项，不能用规划文档冒充自动执行结果。

## 异常恢复

发现不可自动执行的关键系统路径，记录所缺环境或执行器并安排实现；不得省略该路径或手填通过。

## 证据位置

版本测试计划、矩阵、数据清单和具体 SOP；06-iteration-record.md 记录覆盖决定与缺口。
