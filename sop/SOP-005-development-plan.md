# SOP-005 开发计划

**修订：** 3　**状态：** baselined　**适用：** all

## 目的与范围

将已确定设计转成有顺序、边界和验证出口的实施计划，包括多 agent 交接。

## 触发条件

技术设计就绪，需要安排实际实现，或新增依赖使原计划失效。

## 前置条件

SOP-004 的关键决定已确定；需求与任务表可双向追踪。

## 输入

技术设计、任务依赖、当前仓库状态、可用环境、数据及测试准备工作。

## 执行步骤

1. 按依赖排序任务：SOP-009 先按已基线设计建立真实 App、服务、数据库初始化及原生测试 target/runner 的工程骨架；其可运行后，SOP-010/011 准备业务数据及有效失败基线，再安排对应业务实现。骨架准备不依赖预先存在的业务红测或产品 PASS。
2. 为每项任务写明模块/文件边界、输入、产出、完成标准和局部验证方式；区分可独立验证的源码准备与需要工具链/GUI 的实际运行，不把签名或生产凭据作为开始开发的前提。
3. 多 agent 并行时明确文件所有权、共享接口和整合责任，避免覆盖彼此修改。
4. 将迁移、性能/兼容风险、文档/Changelog 更新和完整 E2E 列入同轮交付；不把测试留作后补。
5. 写清恢复工作所需命令、当前状态和下一步；计划调整同步 breakdown、test-plan 及发布预案。

## 输出

可直接执行的 03-development-plan.md，任务顺序、所有权和集成验证计划。

## 成功与失败判据

执行者知道先做什么、写在哪里、如何验收和交接；环境/测试缺口有具体任务，不能以模糊承诺标完成。

## 异常恢复

依赖缺失时优先完成独立任务并记录阻塞；设计变更返回 SOP-004，同步计划后再继续。

## 证据位置

开发计划与 06-iteration-record.md 保存分工、决定和实际进展，不用聊天记录作为唯一交接。
