# SOP-020 部署分发

**修订：** 2　**状态：** baselined　**适用：** all

## 目的与范围

将已验证的同一服务端和客户端产物按兼容顺序部署并分发，自动核对线上结果。

## 触发条件

Git 发布完成，需要部署服务、发布安装包或更新 appcast/更新服务器。

## 前置条件

SOP-019 的有效发布与原始资产；部署授权、目标、受保护凭据、健康标准和已验证恢复预案明确。

## 输入

通行证、实际部署配置、最终资产摘要、数据库迁移/备份报告和发布预案。

## 执行步骤

1. 在受保护任务中核验目标、通行证与下载资产 SHA256，拒绝临时重新构建或未验证包。
2. 先确认备份和迁移前提；必要数据库变化按 SOP-016 使用已验证程序执行。
3. 按预案部署兼容服务端，自动验证已定义健康、版本、认证和数据读写结果；不健康时停止客户端推广。
4. 发布实际安装包并更新相应渠道的分发/appcast，核对签名、版本、下载地址与包摘要；稳定/测试渠道按预案隔离。
5. 自动检查实际客户端更新可见性、服务状态与预期版本；记录真实开始结束时间和结果。
6. v0.1.0内部版按[安装与本机服务](../docs/releases/02-installation.md)核对已发布资产后启动API与 `scripts/local_distribution.py`；已有生产库不重新初始化，回环端口冲突即停止。程序只分发同名通行证绑定的真实100候选，不分发101受控升级测试包。当前候选实际未发布、缺权限或原始资产时保持BLOCKED，不虚构上线。

## 输出

真实部署与分发记录、线上版本/资产摘要及自动健康检查结果。

## 成功与失败判据

线上服务、更新清单和被下载产物均与通行证一致，所有发布后检查通过才完成；请求发出不等于部署成功。

## 异常恢复

任一健康/迁移/分发异常立即停止后续步骤并执行 SOP-021；保留当前线上版本和故障事实，不自动用未验证配置重试。

## 证据位置

受保护部署任务、版本/健康报告、分发清单快照及资产摘要；无生产凭据或用户正文。

## 下一步

成功执行 [SOP-022 归档交接](SOP-022-archive-handoff.md)；失败进入 [SOP-021 回退恢复](SOP-021-rollback.md)。
